# 分区消费演示（本地消息代理 + 租约/任期 fencing + 幂等入账）

一个**纯本地**的消息队列消费者组演示：不依赖 Kafka，用 SQLite 同时充当
消息代理、协调存储和业务库。多个真实的工作进程消费 6 个分区，页面实时展示
分区归属、消费进度、账户账本，以及进程停止/崩溃后任务的转交过程。

## 快速开始

```bash
./run.sh          # 首次运行会建 venv、装依赖、构建前端、播种数据
# 打开 http://127.0.0.1:8000
```

页面上点击「＋ 启动 Worker」启动 2~3 个工作进程，即可看到分区被认领、
消息被逐条消费、账户余额增长。

## 演示场景（页面均有对应按钮）

| 场景 | 操作 | 观察点 |
|---|---|---|
| 正常消费 | 启动若干 Worker | 分区均衡分配，显示持有者、任期号、租约倒计时 |
| 优雅停止 | Worker 卡片「优雅停止」 | 分区**立即**释放并被他人认领 |
| 进程崩溃 | Worker 卡片「强制崩溃」(SIGKILL) | 心跳丢失 → 判定失联 → **租约到期后**分区被回收转交 |
| 提交前退出 | 注入「提交前退出」 | 事务回滚，消息被重新处理，**不会重复入账** |
| 提交后退出 | 注入「提交后退出」 | 提交已生效，确认丢失也无妨，恢复后不重复入账 |
| 旧任期迟到 | 注入「僵尸迟到」 | 进程装死停止心跳，分区被转交后，旧任期的迟到写入与位置提交**被 fencing 拒绝** |
| 分区转交 | 分区卡片选择目标「转交」 | 先撤销旧归属，再登记新持有者，任期号递增 |
| 重复投递 | 分区卡片「重放重复」 | 同一 offset 内容相同 → 跳过入账 |
| 篡改重放 | 分区卡片「篡改重放」 | 同一 offset 内容变化 → 分区停止并显示冲突，人工「跳过该消息并恢复」 |
| 一致性核对 | 顶栏「核对一致性」（每 5s 自动） | 去重记录↔流水一一对应、无重复入账、余额=流水合计、offset 连续且有序 |

可以随时「生产 20 条」或打开「自动生产」制造持续流量；「重置演示」会
结束全部工作进程并重新播种。

## 关键机制

**一个 SQLite 数据库，四种角色**（`data/demo.db`，WAL 模式，各进程各自开连接）：

- `messages` — 本地消息代理，按分区保存，分区内 offset 递增
- `assignments` / `positions` — 分区归属（持有者、任期 epoch、租约到期时间）与消费位置
- `dedup` — 去重记录 `(partition, offset, content_hash)`
- `ledger` / `ledger_entries` — 业务账本与入账流水

**fencing**：工作进程处理每条消息时，在 `BEGIN IMMEDIATE` 事务内先核对
「持有者是我 ∧ 任期未变 ∧ 租约未过期」，然后在**同一事务**里写去重记录、
入账流水、账户余额并推进位置。协调方的撤销/登记也要拿同一把写锁，因此
分区一旦转交，旧持有者的写入和位置提交必然失败——核对与写入之间没有窗口。

**交接**：每次分配/转交都让 `epoch` 递增。进程失联后等租约到期（6s）即可
撤销；优雅退出则主动立即释放。旧进程醒来后的一切迟到写入都会因
「持有者/任期/租约」核对失败而被拒绝，并记入事件流。

**幂等**：重复送达的 offset 若内容哈希与去重记录一致 → 跳过；不一致 →
分区停止、记录冲突，等待人工处理。

## 目录结构

```
app/
  db.py           # schema、连接、事务助手、常量（租约时长等）
  coordinator.py  # 认领/撤销/转交/再均衡、消息生产（worker 与 API 共用）
  worker.py       # 工作进程：心跳续租、fencing 事务处理、故障注入点
  api.py          # FastAPI：状态快照、进程管理、演示操作、一致性核对
frontend/         # React + Vite，构建产物由 FastAPI 托管
scripts/e2e_test.py  # 端到端验收：12 个场景全自动断言
run.sh            # 一键启动
```

## 端到端测试

```bash
./run.sh &                       # 先启动服务
.venv/bin/python scripts/e2e_test.py
```

覆盖：均衡认领、崩溃接管、优雅停止、重复跳过、篡改冲突、三种故障注入、
强制转交，以及每一步之后的一致性核对。

## API 一览

- `GET  /api/state` — 全量状态快照（页面每秒轮询）
- `GET  /api/verify` — 一致性核对
- `POST /api/workers` `{worker_id?}` — 启动工作进程
- `POST /api/workers/{id}/stop|kill` — 优雅停止 / 强制崩溃
- `POST /api/workers/{id}/fault` `{mode}` — 注入故障（`crash_before_commit` / `crash_after_commit` / `zombie`）
- `POST /api/partitions/{p}/transfer` `{target}` — 强制转交
- `POST /api/partitions/{p}/replay|tamper|resolve` — 重放重复 / 篡改重放 / 冲突恢复
- `POST /api/produce` `{count}`、`POST /api/autoproduce` `{on}` — 生产消息
- `POST /api/reset` — 重置演示
